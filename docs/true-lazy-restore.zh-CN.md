# 真正懒恢复方案（设计，尚未实现）

## 用户入口

保留当前原生恢复后的快速 discard。新增扩展自己的“保存当前组”和“懒恢复”入口，由扩展控制标签的创建。用户必须从新入口恢复才能避免后台网页首次加载；点击 Chrome 原生保存组仍受 Chrome 的加载策略影响。

## 保存与恢复

1. 保存组名、颜色、顺序、标签 URL/标题、选中的标签和格式版本。写入成功前不能关闭原组；初版默认仅保存，不自动关闭。
2. 保留可导出、可删除的本地快照；每次恢复有独立操作 ID，防止重复点击创建重复标签。
3. 以有限并发创建扩展自身的轻量占位页，写入持久化 token 到快照条目的映射，再创建原顺序的标签组。默认仅选中页导航到真实 URL。
4. 后台占位页不请求原网站，也不下载远程 favicon。用户激活时才查 token 并导航到真实 URL；导航失败保留可重试占位页。
5. onActivated 与占位页加载时的活动状态检查都触发幂等恢复，覆盖 worker 重启和激活事件早于脚本就绪的情况。状态存入 storage.local；storage.session 只能作为当前浏览器会话缓存。
6. 原生保存组可能重新保存占位 URL；占位 token 的映射必须在删除快照时确认是否仍被引用，并给失效占位页提供明确的恢复/导入入口。

## 数据与安全

原 URL 不放进占位页 query/hash，避免浏览历史暴露完整 URL。使用不透明 token 并验证归属和数据版本。标题使用 textContent，禁止插入网页提供的 HTML。仅恢复经校验的 HTTP/HTTPS；file、chrome、data、javascript 和失效地址显示说明，不能直接导航。隐身数据默认不保存。

快照不等于完整 Chrome 会话：表单内容、滚动位置、POST 请求、页面内存状态和历史栈不保证恢复。固定页的分组约束、关闭窗口、部分创建失败、并行恢复、删除快照和磁盘写入失败都需要明确处理。采用增量状态记录，失败时保留快照及成功创建的标签，并提供继续恢复或撤销入口。

## 验收

- 使用本地 HTTP 服务器统计请求：恢复 50/200 个标签时，未激活的后台条目对原网站的请求为零。
- 点击一项只加载一项，快速切换和重复事件不会重复导航。
- 浏览器重启、worker 重启、关闭窗口、部分创建失败后可继续恢复。
- 组名、颜色、顺序、URL 参数和标题保留；导出/导入有格式迁移。
- 记录恢复总时间、峰值内存和占位页本身开销。占位页仍有标签/渲染成本，不能承诺常数内存。

这属于新增数据管理功能，需要专门界面、迁移及端到端测试，本次只记录方案。
