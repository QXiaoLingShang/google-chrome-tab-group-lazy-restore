<h1 align="center">Tab Group Lazy Restore</h1>

<p align="center">
  <a href="README.md">English</a> · 简体中文
</p>

你是否也遇到过：重新打开 Chrome 中保存的标签组，内存占用就突然上升？你保留了几十个标签页，想着以后还会用到。但重新打开标签组时，这些页面可能一起开始加载，而你只是想继续浏览其中一个。

Tab Group Lazy Restore 会在标签组打开后，释放符合条件的后台标签页。标签页仍留在原来的标签组中，切换过去时再重新加载。你可以继续按原来的方式使用 Chrome 保存的标签组，不过打开时仍可能出现短暂的内存高峰。

## 安装

1. 从 [最新 Release](https://github.com/QXiaoLingShang/google-chrome-tab-group-lazy-restore/releases) 下载 ZIP 安装包。
2. 解压 ZIP 文件。
3. 在 Chrome 中打开 `chrome://extensions/`，启用**开发者模式**。
4. 点击**加载已解压的扩展程序（Load unpacked）**，选择包含 `manifest.json` 的解压文件夹。

## 使用

像平时一样，在 Chrome 中重新打开保存的标签组。扩展会识别新恢复的标签页，自动释放符合条件的后台标签页，并保留当前活动页。当你需要某个已释放的标签页时，切换过去，Chrome 就会重新加载页面。

默认情况下，包含五个或更少标签页的标签组不会被处理。你可以在设置中调整这个数量，也可以保护指定的标签组。

## 配置

打开 `chrome://extensions/`，点击扩展的**详细信息**，然后选择**扩展程序选项（Extension options）**。

- **最少标签页数量**：标签页数量小于或等于该值的标签组不会被处理，默认值为 `5`。
- **受保护的标签组名称**：在最后一行输入标签组名称，按 Enter 或离开输入框后确认。名称与任一条目完全一致的标签组，其标签页不会被释放。
- **等待标签页标题加载（实验功能）**：等待各标签页的标题更新后再释放。如果直到恢复超时仍未收到更新，符合条件的标签页仍可被释放。默认关闭，开启后可能使内存占用在高位维持更久。
- **高级设置**：调整恢复检测、检查延迟、恢复超时、失败重试和同时释放的标签页数量。默认折叠，建议先使用默认值；增加等待时间可能让恢复的页面在内存中保留更久。

设置会自动保存在 Chrome 本地，修改后无需重新构建。设置页支持英文和简体中文，也可以通过**恢复默认设置**重置选项。

## 工作原理

Tab Group Lazy Restore 会在标签组恢复时识别短时间内创建的同一批标签页，然后分批处理：

1. 保留当前活动页。
2. 将符合条件的后台标签页放入限制并发数量的释放队列。开启等待标题的选项后，各标签页会先等待标题更新。
3. 标签页仍保留在原来的标签组中；当你切换过去时，Chrome 再重新加载页面。

扩展不会删除标签页，也不会释放恢复前已经打开的标签页。已固定、正在播放声音或有待完成导航的标签页会被跳过。每次释放前都会再次检查状态；导航、固定或声音状态变化时，也会重新检查仍在跟踪的标签页。新标签页持续到来时，检查也会继续进行，避免整个恢复过程都在等待。

## 使用限制

在扩展来得及释放标签页之前，Chrome 可能已经开始加载多个页面。因此，扩展可以降低恢复后的内存占用，但无法阻止最初的内存高峰，也无法实现真正的懒加载。Chrome 回收内存和刷新统计同样可能需要时间。

恢复检测依据是近期创建的标签页加入同一个标签组。快速新建并分组多个标签页时，也可能触发处理。只有此次跟踪的新标签页会成为释放候选；已有标签页和受保护的标签组不会被处理。

## 开发

从源码构建需要 **Node.js 22.x（最低 22.13.0）、24.x，或 26 及以上版本**，以及 **pnpm 12.6.0 或更高版本**。Node 23 和 25 不在支持范围内。发布流程使用 **Node.js 24** 和 **pnpm 12.11.2**。这些工具只用于开发，安装已发布的 ZIP 包不需要它们。

克隆仓库后，在项目根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test:coverage
pnpm build:dev
```

构建完成后，在 `chrome://extensions/` 中点击**加载已解压的扩展程序**，选择项目根目录。修改源码后，重新构建并点击扩展的重新加载按钮。需要生成安装包时，运行 `pnpm package:release`，ZIP 文件会写入 `release/`。

CI 在 Windows 和 Linux 上检查格式、类型、核心测试覆盖率、开发构建和发布包。与版本号匹配的标签会在检查通过后创建 GitHub 发布草稿。工具版本矩阵、覆盖率门槛、浏览器检查和发布步骤见[贡献指南](docs/CONTRIBUTING.md)。
